# semruler · 版本尺

把 npm 语义化版本区间粘贴进来，画成一把尺子——再把版本号丢上去，红绿立判。

## 解决什么问题

`^1.2.0 || >=3.0.0 <3.2.0` 写起来三秒，读懂要三十秒。几乎人人都因为没搞清 `^` 到底放行什么、或者 `1.3.0-beta.1` 为什么"明明覆盖 1.3.0 却不命中"而踩过依赖升级的坑。**semruler** 把抽象区间画成看得见的图：

- **把区间画上尺子**：绿色色带是匹配区，每个 `||` 分支一条带，端点 `≥ / <` 实时标注
- **预发布规则可视化**：色带左侧的斜纹小块就是大家最容易踩的 npm 规则——预发布版本只能从「同 major.minor.patch 元组」的 comparator 进场（或打开 *含预发布* 开关）
- **版本落尺**：每行一个版本粘进去，尺子上落一个点 + 一行判定——✓ 写明命中哪个分支（`命中第 2 组：≥3.0.0 且 <3.2.0`），✗ 给白话理由（"恰好卡在排他上界 <3.2.0"）
- **三兄弟对比**：`1.2.3`（焊死）、`~1.2.3`（只收补丁）、`^1.2.3`（放行次版本）三把 mini 尺并排，看一眼就记住
- **一键复制 Markdown 报告**：区间、分支、判定表，直接贴进 PR 评论或 issue

## 怎么用

1. 打开 `index.html`（或 GitHub Pages 地址）——已预载示例区间和一批版本
2. 输入任意区间（支持 `^ ~ >= < <= =`、x-range 如 `1.2.x`、连字符区间 `2.1.0 - 2.4.0`、`||` 分支、`*`）
3. 每行粘一个候选版本，看尺子和判定列表
4. 打开「含预发布」模拟 `includePrerelease`；点「复制判定报告 Markdown」分享结论

无法解析的输入诚实降级：区间坏了好心报错不乱画；非法版本号单独一行「看不懂」，不会悄悄消失。

## 技术说明

- 单 HTML 文件，零依赖零构建，`file://` 双击即用，离线可用
- 区间解析与匹配手写实现 npm semver 语义：comparator 脱糖（`^0.2.3` → `<0.3.0`、`<=1.2` → `<1.3.0`、x-range、连字符区间）、预发布标识符比较（数字 < 字母数字、字段数平局规则）、预发布门——全部纯函数，发布前在 Node 里做过单元仿真
- 尺子为程序生成 SVG；色带位置按线性元组空间（major·10⁶ + minor·10³ + patch）精确计算，端点与版本落点不是目测
- 一处已声明的简化：`>1.2.3` 的首个匹配正式版按 `1.2.4` 处理（npm `>` 对预发布的边角语义不在这把"阅读尺"的范围里）
- 无任何网络请求、无存储，数据不出页面
